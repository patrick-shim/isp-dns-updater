# GitHub Release Checklist

Before pushing to GitHub, verify the following:

## Critical Security Checks

- [ ] **config.yaml is NOT committed** - Run: `git status` and verify it's not listed
- [ ] **No credentials in code** - Search for API tokens: `grep -r "41GFo" .` (should return nothing)
- [ ] **No credentials in commit history** - If you've committed config.yaml before, you must clean git history
- [ ] **.gitignore is working** - Run: `git check-ignore config.yaml` (should output: config.yaml)

## Files to Verify

- [ ] `config.yaml` - Should NOT be in git (contains your real credentials)
- [ ] `config.example.yaml` - Should be in git (contains example values only)
- [ ] `.gitignore` - Includes `config.yaml` and `logs/`
- [ ] `LICENSE` - Present and correct
- [ ] `README.md` - Updated with your GitHub username in badges
- [ ] `SECURITY.md` - Present
- [ ] `CONTRIBUTING.md` - Present

## Pre-Push Commands

Run these commands before your first push:

```bash
# 1. Verify config.yaml is not tracked
git status | grep config.yaml
# Should show nothing or "Untracked files" only

# 2. Check for any credentials in tracked files
git grep -i "api_token\|zone_id" -- '*.yaml' '*.yml'
# Should only show config.example.yaml with placeholder values

# 3. Verify .gitignore is working
git check-ignore config.yaml logs/
# Should output both paths

# 4. Check what will be committed
git add .
git status
# Review carefully - config.yaml should NOT appear

# 5. If config.yaml appears, remove it from staging
git reset config.yaml
```

## If You've Already Committed Credentials

If you accidentally committed `config.yaml` with real credentials:

### Option 1: Remove from last commit (if not pushed)
```bash
git rm --cached config.yaml
git commit --amend -m "Remove config.yaml from tracking"
```

### Option 2: Clean entire git history (if pushed)
```bash
# Install BFG Repo Cleaner
# Then run:
bfg --delete-files config.yaml
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# Force push (WARNING: rewrites history)
git push --force
```

### Option 3: Start fresh (safest if credentials exposed)
1. Delete the GitHub repository
2. Revoke and regenerate CloudFlare API token
3. Create new repository
4. Verify .gitignore before first commit

## Initial Git Setup

```bash
# Initialize repository
git init

# Add remote (replace with your GitHub URL)
git remote add origin https://github.com/YOUR_USERNAME/isp-address-updater.git

# Create main branch
git checkout -b main

# Stage all files (config.yaml will be ignored)
git add .

# Verify staging
git status

# First commit
git commit -m "Initial commit: CloudFlare DNS Updater with Docker support"

# Push to GitHub
git push -u origin main
```

## Sharing Your Repository

When sharing:
- Point users to `config.example.yaml` for setup
- Emphasize security in README
- Link to SECURITY.md for credential handling
- Mention the .gitignore protects config.yaml

## Ongoing Maintenance

- [ ] Never commit config.yaml
- [ ] Keep config.example.yaml updated when adding new config options
- [ ] Update SECURITY.md if adding new credential types
- [ ] Test Docker builds before merging PRs
- [ ] Review PRs for credential leaks

## Emergency: Credentials Exposed

If you accidentally push credentials to GitHub:

1. **Immediately revoke** the CloudFlare API token
2. Generate a new token
3. Update your local config.yaml
4. Clean git history (see above)
5. Force push or delete/recreate repository
6. Review CloudFlare audit logs
